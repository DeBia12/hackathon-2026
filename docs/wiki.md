CONTEXT
 
We are participating in an Accenture agentic-development hackathon.
 
Challenge theme:

FINANCIAL INCLUSION.
 
The goal is to support basic financial literacy for people with low financial knowledge.
 
This must NOT be a financial adviser, investment recommender, product comparison engine or investment-selection tool.
 
The product must educate, improve understanding and demonstrate measurable learning.
 
==================================================

1. PRODUCT VISION

==================================================
 
Build an interactive financial-literacy platform for young adults aged approximately 18–30 who start with little or no financial knowledge.
 
The educational scenario is:
 
“From saving to investing: understanding risk, return and diversification well enough to distinguish the main characteristics of government bonds, corporate bonds, stocks and ETFs.”
 
The platform must NOT simply present articles or definitions.
 
The learning model is:
 
ASSESS

→ LEARN

→ INTERACT

→ VERIFY

→ APPLY

→ MEASURE IMPROVEMENT
 
The primary product promise is:
 
“We don't tell you where to put your money.

We help you understand what financial concepts and instruments actually mean.”
 
The application language must be ITALIAN.
 
The visual identity should feel like a modern professional fintech product:

clean, accessible, trustworthy and slightly gamified, but not childish.
 
==================================================

2. TARGET USER

==================================================
 
Primary user:
 
- age approximately 18–30;

- little or no financial education;

- may have heard words such as inflation, stock, bond or ETF;

- does not necessarily understand what they mean;

- wants to build enough basic knowledge to understand financial information independently.
 
Assume ZERO prior knowledge.
 
Avoid unnecessary jargon.
 
When jargon is necessary, explain it immediately.
 
==================================================

3. CORE USER JOURNEY

==================================================
 
The experience must be guided and sequential.
 
STEP 1 — Initial Financial Literacy Check
 
The user completes 5 short questions.
 
The questions should assess different prerequisite concepts without being intimidating.
 
The initial assessment produces:
 
- overall score;

- concept-level understanding;

- an initial financial-literacy profile.
 
Example visual result:
 
Financial Literacy Score

40%
 
Money basics          80%

Inflation             20%

Risk & Return         40%

Diversification        0%

Financial instruments 20%
 
This represents the BEFORE measurement.
 
STEP 2 — Guided Learning Journey
 
The user follows a mandatory learning path.
 
Modules unlock progressively.
 
Suggested progression:
 
MODULE 1

Money, saving and purchasing power
 
Teach:

- what saving means;

- nominal money vs purchasing power;

- introduction to inflation.
 
MODULE 2

Inflation
 
Teach:

- why €100 can buy less in the future;

- nominal value vs real purchasing power.
 
Include a simple interactive visualization.
 
MODULE 3

Saving vs Investing
 
Teach the conceptual distinction.
 
Do NOT claim that one is better than the other.
 
Explain that different uses of money involve different objectives, uncertainty and time horizons.
 
MODULE 4

Risk and Return
 
Teach:

- what financial risk means;

- that future outcomes are uncertain;

- difference between guaranteed/promised cash flows and uncertain market value where appropriate;

- why return cannot be discussed meaningfully without discussing risk.
 
Avoid predictions and expected-return recommendations.
 
MODULE 5

Diversification
 
Teach the concept visually.
 
Example educational interaction:
 
Scenario A:

one company
 
Scenario B:

multiple companies
 
Apply the same hypothetical negative event to one company and visually show how concentration changes the impact.
 
This is purely educational.
 
Do NOT state that a diversified portfolio is the “correct” investment for the user.
 
MODULE 6

Understanding Financial Instruments
 
Use the concepts learned so far to explain:
 
1. Italian government bond / BTP

2. Corporate bond

3. Stock

4. ETF
 
The purpose is NOT to compare performance.
 
The user must understand what each instrument fundamentally represents.
 
==================================================

4. MICRO-LESSON FORMAT

==================================================
 
Every lesson should follow the same pattern:
 
SEE IT

→ visual representation or analogy
 
UNDERSTAND IT

→ maximum a few short paragraphs of simple explanation
 
TRY IT

→ small interaction or simulation
 
PROVE IT

→ one knowledge-check question
 
MASTERED

→ user receives progress/mastery feedback
 
Avoid long educational pages.
 
Learning should happen primarily through interaction.
 
==================================================

5. ADAPTIVE LEARNING ENGINE

==================================================
 
This is an important software capability.
 
The platform must track concepts independently.
 
Example concepts:
 
- saving;

- inflation;

- purchasing power;

- risk;

- return;

- diversification;

- ownership;

- lending/debt;

- government bond;

- corporate bond;

- stock;

- ETF.
 
If the user answers a verification question incorrectly:
 
1. identify the concept gap;

2. do not simply display “wrong”;

3. redirect or recommend the prerequisite micro-lesson;

4. show the relevant explanation/interactivity;

5. re-test the concept with a DIFFERENT question;

6. mark the concept as mastered only after successful verification.
 
Example:
 
Incorrect answer:

“Buying a corporate bond means owning part of the company.”
 
System detects:

Concept gap = OWNER vs LENDER
 
System shows:

micro-lesson “Owner or lender?”
 
Then performs a new check.
 
This adaptive behaviour must be visible during the demo.

6. FINANCIAL INSTRUMENT EDUCATION

==================================================
 
Use REAL financial instruments as examples, but DO NOT use live market data.
 
Use controlled, static educational information.
 
A — Government bond
 
Use a real Italian BTP as the educational example.
 
Teach:
 
- issuer = Italian government;

- investor is lending money to the issuer;

- maturity;

- principal;

- coupon where applicable.
 
Key learning question:
 
“Acquistando un titolo di Stato diventi proprietario dello Stato?”
 
Answer: No.
 
B — Corporate Bond
 
Use a real corporate issuer/example.
 
Teach:
 
- issuer = company;

- investor is creditor/lender, not owner;

- principal;

- coupon;

- maturity;

- issuer risk concept.
 
C — Stock
 
Use a real listed company as an example.
 
Teach:
 
- a share represents ownership in a company;

- ownership differs fundamentally from lending;

- market value may change;

- shareholders participate in company ownership.
 
Use a visual ownership representation.
 
D — ETF
 
Use a real broad-market ETF as an educational example.
 
Teach:
 
- ETF is a fund traded on an exchange;

- it can contain many underlying instruments;

- connect it directly to the previously learned diversification concept.
 
Do NOT show:

- recent performance;

- expected performance;

- target returns;

- buy/sell signals;

- rankings;

- “best ETF” language.

This prevents memorization from being mistaken for learning.
 
Calculate:
 
BEFORE SCORE

vs

AFTER SCORE
 
Example:

  40%      →        80%

“We don't measure how much content the user consumed.

9. MANDATORY HACKATHON DELIVERABLES

==================================================
 
USER DIFFICULTY STATEMENT
 
Young adults with little financial education frequently encounter concepts such as inflation, risk, bonds, stocks and ETFs without understanding the relationships between them.
 
This makes financial information inaccessible and creates a cognitive barrier to making informed decisions.
 
The platform reduces this barrier by building financial knowledge progressively from basic concepts to real-world financial instruments.
 
BEFORE / AFTER SIMPLICITY EVIDENCE
 
Before:
 
The user sees concepts such as:
 
BTP

Corporate Bond

Stock

ETF

Risk

Return

Diversification
 
but cannot reliably explain the differences.
 
After:
 
The user can identify:
 
- whether they are owner or lender;

- who the issuer is;

- what risk means;

- what diversification means;

- the basic structure of each instrument.
 
The improvement is demonstrated through the initial and final assessments.
 
RISK & CLARITY NOTE
 
The application is strictly educational.
 
It:
 
- does not recommend investments;

- does not suggest what the user should buy or sell;

- does not rank financial products;

- does not predict returns;

- does not personalize investment decisions;

- does not identify a “best” instrument.
 
Financial definitions and real-instrument characteristics must remain factually accurate.
 
Simplification may change language and visual representation, but must never change the financial meaning.
 
Real instruments are used only as educational examples and use controlled static information rather than live market data.

13. ACCEPTANCE CRITERIA

==================================================
 
The demo is considered successful when:
 
- a first-time user can complete the assessment;

- an initial literacy score is generated;

- learning modules unlock sequentially;

- an incorrect answer triggers the appropriate remediation flow;

- the user can complete the remediation and be re-tested;

- mastery state updates correctly;

- BTP, corporate bond, stock and ETF are clearly distinguishable;

- no screen recommends what the user should invest in;

- final assessment uses different questions from the initial assessment;

- before/after improvement is calculated and displayed;

- the primary journey works end-to-end without manual intervention;

- automated tests cover core scoring/adaptive-learning logic;

- the final flow is verified through the browser.
